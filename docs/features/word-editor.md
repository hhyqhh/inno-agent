# Word 文档编辑（试用接入）

工作区 DOCX 预览文件栏的「编辑」在预览面板内打开分页编辑器，不弹出全屏对话框。使用 Apache-2.0 的 BetterOffice 0.5.0 引擎与 React 组件，不需要 ONLYOFFICE 服务、商业密钥或外部文档上传。当前支持 DOCX，最大 32 MB；旧 DOC 文件继续使用 PDF 预览，可先用 Word/WPS 另存为 DOCX。

## 界面与功能

参考产品截图，采用单条文件栏、七个页签、紧凑圆角工具栏、居中纸张与引擎原生缩放控件。文件栏由预览与编辑两种模式共享：左侧为文件名与所在文件夹提示，右侧按模式提供编辑入口或保存状态、保存、下载副本与返回预览；窄面板下操作收纳为图标按钮，页签与工具行横向滚动。宿主按钮使用共享 UI，第三方控件通过语义变量适配 light/dark。

| 板块 | 已接入功能 |
| --- | --- |
| 开始 | 撤销重做、字体字号、粗体斜体下划线、文字和高亮颜色、列表、行距、对齐、段落样式、查找 |
| 插入 | 图片、表格、链接、分页符 |
| 页面 | 原生页面设置、下一页分节、水印 |
| 引用 | 插入目录、查找 |
| 视图 | 全屏、大纲、标尺、缩放、100% |
| 表格样式 | 重复标题行、全部/外侧/无边框、原生表格属性 |
| 表格布局 | 删除行列或表格、上下插行、左右插列、合并拆分、原生表格属性 |

七个页签常驻，具体命令由引擎按选区判断是否启用；合并单元格需要相应选区。当前不包含评论、修订和多人协作。引用页签尚不提供脚注、尾注和题注，其他页签也没有完整复刻截图的所有工具。采用实际 npm 发布版本的公开 API，不能将七个板块理解为完整 Word 功能兼容。

## 数据与保存

- 编辑器内嵌在预览面板中，直接参与页面布局；BetterOffice 挂在 body 的输入框和弹出层无需弹层隔离即可获得焦点。关闭确认、跨页签的未保存确认使用共享模态对话框。
- 浏览器引擎持有唯一活动草稿；编辑会话由稳定的工作区容器持有并固定文件所属工作区。调整宽度、切换页签（编辑器隐藏但草稿保留）或后台导航不会重建编辑器或改变保存目标；关闭会话页签或打开其他文档时，未保存的草稿会先触发确认，可选择继续编辑、放弃或保存后关闭。
- Ctrl/Cmd+S 或保存按钮将引擎生成的 DOCX 通过同源 PUT 写回；已保存状态以服务器确认时间为准。序列化期间的新编辑继续显示未保存。
- 刷新/关闭浏览器使用原生未保存提醒；当前没有草稿跨刷新恢复和自动保存。
- `office/word-document.ts` 是保存的唯一入口。读取返回 SHA-256 ETag，保存使用 If-Match 比较原文件版本。服务内串行写入；外部文件改变返回 409，保留浏览器草稿，可下载副本。外部应用不共享锁协议时，摘要检查与原子替换之间仍存在竞争窗口。
- 首次写回某一版本前，在 `<dataDir>/office/originals/<sha256>.docx` 保存原件；临时文件原子替换工作区目标，并保留文件权限。备份暂不自动删除。
- 路由只接受所属工作区内的普通 DOCX 文件，进行异步路径及符号链接检查、32 MB 限制、ZIP 文件头检查。不是完整 OOXML 结构校验器；解码由浏览器引擎完成。

## 字体与运行

运行常规 `npm run build`，启动后端即可，无需 Office 容器。构建目标为 ES2022，以支持 HarfBuzz WASM 模块加载；需要当前桌面壳或现代浏览器。

字体由 `@betteroffice/fonts` 0.4.1 与 `@betteroffice/fonts-cjk` 0.4.0 经 Vite 打包，通过同源服务加载，不依赖字体 CDN。中文 Word 字体名映射为 Noto Sans/Serif SC 等替代字体，浏览器与 WASM 使用同一字体文件进行测量。上游 CJK 包只含 Regular 字重，粗体中文会按 Regular 度量却画出常规轮廓；`react/office/word-fonts.ts` 在此之上补充 Noto Sans/Serif SC Bold（同一 Noto CJK Subset-SC 构建，SIL OFL，许可证文本随字体目录附带），使粗体中文按真实粗体度量与绘制。基础字体包约 14.2 MB，CJK 包约 33 MB，按引擎需求加载；替代字体的分页与 Word/WPS 仍可能不同。行距方面 docGrid 行网格与宋体垂直度量已按 Word 规则生效。两端对齐在引擎内已改为按 Word 方式分摊行尾富余：`w:jc="both"` 的剩余宽度平分给空格与东亚字间边界（汉字/假名/谚文/全角标点等，见 `ooxml-text` 的 `is_east_asian_justify_char`），纯西文行保持只拉伸空格、段末行不拉伸；绘制、选择、光标与命中几何同源于该显示列表。该修改位于 `runtime/bo-756`（基于上游 gitHead 756b9205 = npm 0.5.0）并编译进 `vendor/betteroffice/` 下的 layout 与 edit 两个 WASM 核心，`scripts/apply-betteroffice-justify-fix.mjs` 在每次依赖安装后（根 package.json 的 postinstall）把配套核心换入 node_modules 并按哈希幂等。上游仍未实现 `compressPunctuation` 标点压缩与 `balanceSingleByteDoubleByteWidth`，满行中文在 Word 能排下时此处可能仍提前折行（本样例差约 9.4px，即约一个标点的半格压缩量），这是与 Word 剩余的主要排版差异。分发版权与 SIL OFL 文本见 `web/public/fonts/word/` 与 `src/react/office/fonts/`。保存先等待 `flushPendingInput()` 完成，再生成 DOCX，以包含输入法待提交内容；真实系统输入法仍需人工验收。

当前属于试用实现，不能作为已验收的生产编辑器：已在申请表样例中复现 BetterOffice 0.4.3 导出同时带有同一命名空间的 `ns1:Ignorable` / `mc:Ignorable`，造成 XML 重复属性。引擎自身能重开，严格 XML 解析却失败；宿主在写回或下载前先用 `repair-word-export.ts` 做最小修复——仅当同一开始标签上多个 `*:Ignorable` 属性经该标签声明的 `xmlns` 解析到同一命名空间时，保留规范的 `mc:Ignorable` 并删除其余重复项（唯一已复现形态：`word/document.xml` 根元素，`ns1` 前缀无其他使用；xmlns 声明与可解析性不满足该形态的内容一律不动），随后仍对导出包中的 XML/关系部件做浏览器 DOMParser 校验，失败则拒绝写回或下载，保留草稿与原文件。校验不是 OOXML schema 校验，也不能保证 Word 排版保真；修复只针对已复现的重复属性形态，其余缺陷仍需上游修复并重新验收后再推广。

复杂合并表格、长文、浮动图片、页眉页脚及 Word/WPS 往返保真仍需用真实业务样本验收，特别是中文输入法组合输入。单元测试模拟引擎，只能覆盖宿主生命周期、命令接线与存储流程，不能证明排版保真。

## 分节分页边界（0.5.0 已修复）

「手动分页符紧跟『下一页』分节符」的结构在 BetterOffice 0.4.3 会多渲染一张空白页：引擎把空分节段落单独放到一页，正文再起一页；Microsoft Word 将两个重合的换页边界合并为一个，同一结构只有 2 页。该差异在无头 `exportDocxStructuredWithPages` 中即可复现，与宿主容器、图片下载、字体异步加载无关（复核样本与最小构造样本见调查记录；原件备份在 Word 中第 2 页为摘要，0.4.3 却推到第 3 页）。此前一版文档把该现象记为"Word 忠实渲染、非缺陷"，该结论有直接反证，已纠正。上游 0.5.0 修复了边界合并：升级后最小样本 2 页、原件摘要回到第 2 页，`page-only` / `section-only` 及连续两个分页符产生的合法空白页保持不变。回归测试见 `web/src/react/office/engine-pagination.test.ts`（真实 WASM 引擎，覆盖合并边界、单独分页符、单独分节符、双分页符空白页与奇偶分节起始）。注意：0.5.0 无头快照尚不为奇偶页分节生成填充页（`parityFiller` 恒为 false），与 Word 仍有差异，测试中已钉住现状。

0.5.0 升级随附两项已知问题：编辑器画布在部分环境下会把页面内容重复合成绘制（逻辑层——无头分页、a11y 文档树、页面镜像文本与保存字节均正确，位图却出现偏移重复；0.4.3 无此现象，需上游修复）；0.5.0 改用 `new Worker(new URL(...))` 启动排版引擎，要求 Vite `worker.format: "es"`（已在 `vite.config.ts` 配置）。

## 旧式 VML 图形

BetterOffice 0.4.3 不渲染没有 `v:imagedata` 的 VML 矢量图形，且其形状导出器会把自定义路径写为矩形。经确认采用内嵌 SVG：`prepare-vml.ts` 在浏览器内将独立 `w:pict` 转为 SVG 媒体及标准 DrawingML 图片引用，交由同一编辑器负责分页、锚点、缩放和保存。不使用截图或固定位置的 DOM 覆盖层，不修改磁盘原件。正文、页眉和页脚均经过此适配。

当前支持矩形、圆角矩形、椭圆、直线、折线，以及包含绝对/相对直线、三次/二次贝塞尔曲线和椭圆象限的自定义路径；解析共享 `v:shapetype`、`adj` 和常用公式，保留尺寸、坐标原点、旋转、翻转、基本填充、轮廓与页面/段落锚点。SVG 保持矢量清晰度，在编辑器中以图片整体操作；不提供形状控制点编辑。导入包中以 `mc:Choice` 提供现代图片，原 VML 留在 `mc:Fallback`；BetterOffice 保存后保留 SVG 媒体，原 VML 表达不保证保留。已有现代 Choice 和 VML 图片不会重复转换。

这不是完整 VML 实现。分组、文本框、WordArt、复杂画笔/阴影/渐变和部分圆弧命令尚不转换。遇到不支持的独立图形时保留输入字节，并以只读方式打开，明确提示且禁止保存/下载，避免被当前引擎静默丢弃。图形 XML 不作为 HTML/CSS 注入页面，公式不执行脚本，生成的 SVG 不带外部资源或脚本；路径、公式及解压体积都有上限。

验证包含合成图形用例、实际安装的 BetterOffice WASM 导入器与导出后重开；数学试卷样本的 12 个图形可全部转换。测试校验编辑后的文字及 SVG 媒体字节保留，不能仅以图形数量判断保存正确。渲染及往返验证不代表完整 Word 排版兼容。
