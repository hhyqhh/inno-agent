# 笔记功能迁移计划

## 目标

以 `upstream/main` 为基线，将 `dev` 分支中的笔记与知识管理功能重新迁移到 PR 分支。

迁移时遵循以下原则：

- 按功能逐项迁移，不直接合入 `dev` 的全部提交。
- 每项功能独立验证、独立提交。
- 对包含多个功能的旧提交，按文件和代码块拆分。
- 不带入与笔记功能无关的 `dev` 改动。
- 全部功能迁移完成后，再执行完整构建、测试和提交历史检查。

## 功能清单

### 1. 笔记核心

状态：迁移中（1.1 草稿创建与管理已完成）

#### 1.1 草稿创建与管理

状态：已完成，待提交

范围：

- 创建草稿并保存到 `raw/notes/*.md`。
- 草稿列表、搜索、打开、标题与 Markdown 正文编辑、保存和删除。
- 草稿直接接入 Milkdown/Crepe 编辑器，支持所见即所得的 Markdown 编辑、外部内容同步和加载失败时的源码模式降级。
- 最小 Frontmatter 读写：`note_id`、`title`、`status`、`created`、`updated`。
- 草稿路径校验、非法文件隔离和未保存修改保护。
- 草稿删除沿用 `dev` 的统一确认弹窗、`DELETE /api/l2/notes?path=...` 接口及删除后列表刷新行为。
- 笔记本中的“草稿 / 知识库”基础入口。

本阶段不包含：归档、已归档笔记删除、标签和日期属性编辑、附件、模板、文件导入及 AI 能力。

验收：

- 草稿服务定向测试通过。
- 后端与 Web TypeScript 检查通过。
- 完整前后端构建通过。
- Markdown 编辑器的加载、输入、保存、删除、切换草稿和未保存保护交互通过验证。

说明：Milkdown/Crepe 是 1.1 草稿编辑链路及对应 1.6 前端工作的组成部分，需随草稿功能一起完成验收。

- 完善 Frontmatter 解析、序列化、默认值、旧数据兼容和异常处理。
- 明确可编辑字段、系统字段和后续功能使用的扩展字段边界。
- 同步完成对应的服务与 API 类型、前端 store 字段和属性编辑入口。

依赖：1.1。

验收：Frontmatter 往返、缺失字段、非法 YAML、旧格式兼容和状态转换测试通过；对应 API、store 和属性编辑交互通过验证。

#### 1.3 笔记后端服务与 API 收敛

状态：贯穿实施（1.1 对应部分已完成）

实施方式：本项不单独排期或单独作为后续补齐项，而是随 1.1、1.2、1.4、1.5 的每个功能切片同步完成。

范围：

- 只实现当前功能切片所需接口，不为尚未迁移的能力提前加入空壳接口。

依赖：随对应功能阶段实施；公共类型以 1.2 为基础。

验收：每个功能阶段的服务与路由测试同时通过；路径穿越、文件缺失、请求体非法等错误返回稳定。
